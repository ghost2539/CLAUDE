Portal de Operações SPARE

Plataforma web da operação SPARE para o ciclo de vida de ativos de TI de loja — recebimento, triagem, reparo, identificação, saída de estoque e chamados — integrando EBS, ServiceNow e Correios em um só serviço.

PostgreSQL / MySQL

01 Visão geral

Um único serviço FastAPI serve a SPA do portal, três páginas autônomas fora do menu e toda a API REST. Dois módulos rodam no mesmo processo, mas com banco de dados próprio e isolado.

02 Acesso e autenticação

A tela de login oferece três tipos de acesso. As ações de escrita no ServiceNow ocorrem sempre como o usuário logado — nunca com conta de serviço.

BotãoTipoO que faz
Logon ADADValida no EBS/AD corporativo. Cria o usuário no primeiro acesso.
Logon RedeSSOValida no loginsso (Oracle Access Manager). Só entra quem um administrador liberou (allow-list por usuário de rede).
Logon LocalLOCALUsuário/senha no próprio portal (hash bcrypt); permite troca de senha.

Regras de segurança

  • Sessão por cookie assinado (itsdangerous), HttpOnly, expira em 480 min (configurável).
  • Bloqueio por tentativas (Local): 5 senhas erradas ⇒ 15 min bloqueado.
  • Rate limit: login 5/min, API 120/min por IP.
  • Liberação SSO: usuários de rede nascem sem liberação (allowed=false) e só entram após um admin liberar em Parâmetros → Usuários e Permissões.
  • Sessão ServiceNow: o portal guarda os cookies SSO do usuário; há endpoints para checar (/api/auth/sn-session) e refazer (/api/auth/sn-relogin) sem deslogar.
Permissões por módulo: cada usuário tem can_view, can_create, can_edit, can_export, can_admin. Administradores têm acesso total; o menu só mostra o que o usuário pode ver.

03 Módulos do portal

Nove entradas no menu lateral. Módulos com várias telas usam sub-abas.

3.1

Bem-vindo

Página inicial com boas-vindas e atalhos. Sem escrita.

3.2

Consulta

Busca de ativos por qualquer identificador (imobilizado, ativo, etiqueta, série).

  • Busca em lote (cola vários identificadores; deduplica; até 1000) e busca individual.
  • Cruza base local + EBS e aplica as regras de classificação (categoria/modelo).
  • Exporta o resultado em Excel (.xlsx).

POST /api/consulta GET /api/consulta/single POST /api/consulta/export

3.5

Integração operacional com o ServiceNow.

04 Páginas autônomas

Acessadas direto pela URL, sem passar pelo menu do portal.

/tv

Painel de Operações (TV)

Dashboard leve para exibir em TV: estatísticas, gráficos (categoria, status) e últimos recebimentos; atualiza sozinho em intervalo configurável. Fonte: banco do portal.

/tv?demo=1 preenche com dados aleatórios para validação visual.

/tv2

Controle de Orçamento (CAPEX/OPEX)

Dashboard React de acompanhamento de orçamento de portfólio. Também em /controle-orcamento.

  • Módulo oculto: não aparece no menu; acesso direto pela URL.
  • Acesso livre (sem login); grava quem alterou (usuário logado ou IP). Escritas passam por rate limit.
  • Banco exclusivo (database_orcamento.py; SQLite por padrão, MySQL no servidor novo). Tabelas budget_projects e budget_categories.
  • Assets são o build de frontend/controle-orcamento, versionado porque o servidor não tem Node.js.
/indicadores

Indicadores RMR

Painel dos indicadores mensais da apresentação RMR. Banco próprio (indicador_snapshot, JSON por mês). Leitura no ServiceNow pela API REST com a conta de serviço (SIS.ZABBIXDCSN), somente leitura, via Aggregate API. Carregamento isolado: erro aqui não derruba o portal.

  1. Tickets resolvidos (12m) + SLA — grupo TI_N2_FLD_RNR_LOJAS_SPARE, fechados no ano, estado ≠ Cancelado; SLA por task_sla (has_breached).
  2. Top 20 lojas e Top 10 subcategorias.
  3. TMA (Coletor / SLED / PDV) — incidentes abertos e fechados no mesmo mês; TMA = dias entre "Data Bouncing" (u_data_bouncing) e a resolução, média por subcategoria.

05 Integrações externas

EBS — Oracle E-Business Suite

Login AD e consulta de ativos no ERP corporativo (ebs_service.py). Toda configuração vem de config.py. Fallback: base local de ativos (local_assets) quando o EBS não responde.

ServiceNow — renner.service-now.com

  • Escrita como usuário logado: login por SSO/OAM e reuso dos cookies da sessão. Usado em entrada, saída e encerramento.
  • Leitura por conta de serviço: API REST (/api/now/table/… e Aggregate /api/now/stats/…) com SIS.ZABBIXDCSN, usada pelos Indicadores.
  • Proxy de saída SN_PROXY (ex.: http://10.115.30.135:8888), com interceptação TLS (self-signed ⇒ verify=False).
  • Tabelas: alm_hardware, incident, task_sla.

Correios — API oficial

Autenticação com cartão/contrato, rastreio de objetos e comprovante. Credenciais no cofre vcreports_secret (CORREIOS_USUARIO, CORREIOS_CHAVE, CORREIOS_CARTOES, CORREIOS_DR, CORREIOS_CONTRATO), com fallback para env.

Subir o serviço

cd /var/www/vcreports/portal-spare
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python3 main.py            # ou via systemd (portal_spare.service)

Na subida, init_db() cria as tabelas e grava as configurações padrão. A migração para o servidor novo está em docs/MIGRACAO_SERVIDOR_NOVO.md (MySQL/MariaDB, cofre de segredos, cópia dos três bancos).
